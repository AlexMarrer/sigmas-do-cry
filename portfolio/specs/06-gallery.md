- Masonry (`margin-top: 28px`) is a **CSS grid the page places every tile into**, not `column-width`. `grid-template-columns`, `grid-auto-rows` and `column-gap` are bound from `grid()`; `row-gap` is 0 (the vertical gap is rounded into each tile's row span). Sizes are `cqw` against `.gallery__trip` (`container-type: inline-size`), so the prerendered layout keeps its proportions at any width. Row unit 4px, gap 18px, both expressed against the measured width. Past 9 photos a `.btn.btn--secondary` follows at `margin-top: 28px` reading "Show all N photos" ⇄ "Show fewer", `aria-expanded` + `aria-controls` on the masonry's id.
- **Double-width tiles**: a photo with ratio ≥ 1.3 that is every 4th such photo spans two columns — only from 3 columns up, and only when the shorter of the two columns would not be padded by more than 25% of the tile's height (`WIDE_RATIO` / `WIDE_EVERY` / `WIDE_WASTE_LIMIT`, all in the page). On `korea-2025` that is 3 of 46.
- Cell = `<div>` wrapping the tile, carrying the grid placement and the reveal (`reveal--fade-in-up`, `[revealDelay]="(column - 1) * 80"` → tiles at the same height cascade left to right), `align-self: start` so it keeps its own height inside the rounded row span. Tiles past the cap also get `[revealAlways]` — they can only exist because "Show all" was clicked, so they play the entrance even when they land in view.
- Tile = `<button>` (opens lightbox): background `shot.tone`, `aspect-ratio: shot.aspect`, radius 16px, `position: relative; overflow: hidden`, hover/`focus-visible` `scale(1.015)` .45s `cubic-bezier(.2,.8,.2,1)`; caption abs left 16 / bottom 13, white .9, 12px w550 ls .02em; number abs right 16 / top 13, white .55, 11px tabular.

## States & interactions

All page-local signals (they die with the page; no service, unlike the hover state which is cross-component):

- `place: string | null` · `year: number | null` — one selection per axis. `matching` filters `galleryTrips` by both; `groups` maps it to `{ trip, open, hidden, columns }` view models so the template stays dumb.
- `expanded: Set<string>` — trip slugs whose masonry is uncapped, toggled by the "Show all" button.
- `width: number` — measured off any element in the content column, quantised to 32px and kept current by a `ResizeObserver` (⚠ B3 teardown). `grid()` derives the column count (`floor((width + 18) / (320 + 18))`) plus the `cqw` gap and row unit; `pack()` turns a photo list into placed tiles.
- `lightbox = signal<{ trip: string; index: number } | null>(null)`, keyed by **slug**, not by trip index — filtering renumbers the visible trips. Tile click/Enter ⇒ `lightbox.set({trip: slug, index})`; everything else in lightbox.md.
- `@defer (when lightbox() !== null)` around `<app-lightbox …>` — CDK stays out of the initial bundle until the first open.
- Filters mirror to `?place=&year=` (see landmines). Both are validated against the derived option lists on read, so a hand-typed `?place=Narnia` is ignored rather than rendering an unexplained empty page.
- Empty state distinguishes "filtered to nothing" (offers a clear-filters button) from "no trips in the data at all".

## ⚠ LANDMINES

- **E1** — tiles are `<button type="button">`, not clickable `<div>`s (keyboard + AT). Reset button chrome in CSS; give them a `:focus-visible` outline — the scale alone isn't a focus indicator.
- **D6** — the masonry orders content down each column, so DOM order ≠ visual order; that's acceptable here (tab order stays logical per column), but don't "fix" it by reordering data. When real photos land: every tile keeps its `aspect-ratio` box (space always reserved ⇒ no CLS from lazy loads) and images become `ngSrc` + width/height, lazy by default. `sizes` is **not** the `320px` column-width — columns stretch to ~455px, so it's `(max-width: 660px) 100vw, (max-width: 1080px) 46vw, min(31vw, 460px)`; see [photos.md](photos.md) § Frontend consumption.
- **B5** — `@for (trip of trips; track trip.name)`, inner `@for (shot of trip.shots; track shot.caption)`.
- Captions double as future `alt` text — they're already in the data; wire them when `<img>` replaces the tone `<div>` background.
- **A5 — the prerendered page is the UNFILTERED one.** `?place=` may only reach the signals *after* hydration, or the client's first render has fewer trips than the HTML it is hydrating. Hence a `route.snapshot.queryParamMap` read inside `afterNextRender`, not a bound input (which is why C3 does not apply here). Read once, not watched — consistent with the replace-in-place write below.
- **The URL mirror is not a navigation.** `router.navigate(…, {replaceUrl: true})` re-runs the router for a query-param change, and `withViewTransitions` starts a document view transition per chip click — two quick clicks abort each other with `InvalidStateError: Transition was aborted`. `Location.replaceState()` writes the same URL without any of it.
- **The reveal and the hover scale both own `transform`** (the warning in scroll-reveal.md). They cannot share an element: `.reveal--in`'s 0.8s transition and the tile's 0.45s hover transition overwrite each other's `transition` shorthand, and whichever loses stops animating — the fade would snap. Hence the wrapper cell; the tile keeps hover/focus.
- **Stagger by column, never by running index.** `[revealDelay]="c * 80"`: each cell owns its IO and fires when *it* scrolls in, so an accumulating `i * 80` would leave photo 40 invisible for 3.2s after it was already on screen. With real columns `c` is known, so the cascade is honest — tiles at the same height enter left to right.
- **Cap by slicing from the START** (`photos.slice(0, 9)`), never by filtering: every tile keeps the index it has in `trip.photos`, which is the index the lightbox pages through — and `distribute()` walks photos in order, so slicing before distributing puts the first nine in the same columns they'd occupy in the full set.
- **D6 — `column-fill: balance` cannot hold an arrangement still, which is why this page packs the photos itself.** Balancing is not bin-packing: the browser derives ONE target height from the total and fills columns to it in order, so the tiles per column depend on how many tiles exist. Measured on `london-2026`: expanding 9 → 17 moved photo 04 from the top of column 2 to the fourth slot of column 1, and photo 08 from column 3 to column 2 — DOM order never changed, only the layout. Two separate containers (first attempt) fix the reshuffle but each keeps its own ragged bottom, so the seam tears a hole across the short columns. The skyline pass in `pack()` has neither problem: it is deterministic (relative height = `photo.height / photo.width`, no DOM measurement), and appending cannot move what came before — verified pixel-identical on expand *and* on collapse, for 9 → 17 and 9 → 46. Bonuses: the top row reads 01 02 03 instead of multicol's 01 04 07, and column spans become possible at all.
- **A wide tile has to wait for both its columns, so the shorter one gets padded.** Picking the slot by lowest top alone left three 240–300px holes in `korea-2025`; scoring `top + unevenness` and demoting a tile that still wastes more than `WIDE_WASTE_LIMIT` back to one column brought that to a single 87px one and shortened the grid by 500px. Both decisions read only the current skyline, so the stability above survives them.
- **NG02953 — `sizes` is inside NgOptimizedImage's post-init guard**, like `loaderParams` before it (see the note in `data/gallery.ts`). A tile that flips between one and two columns needs a different `sizes`, and mutating it throws *in the middle of the update pass*: the first cell had been written, every later cell kept its previous grid placement, and the layout silently disagreed with `grid-template-columns`. Hence `track tile.photo.id + tile.columnSpan` — a span change re-creates the tile instead of mutating it. The symptom to recognise: a partially updated view where an interaction "fixes" it.
- **The column count costs one re-layout after hydration.** It is measured, and the prerendered HTML has to commit to something (`ASSUMED_WIDTH = 1400`, four columns), so any client that measures differently re-places every tile once. Cheap, because only inline styles change — the `cqw` sizing is what keeps the pre-measurement frame proportional instead of broken. Do **not** try to fix it by measuring before the first render: that is exactly the hydration mismatch A5 is about.
